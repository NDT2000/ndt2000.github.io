01 / Financial dataPersonal project · In development

Financial insights start with numbers you can trust.

Personal Finance Tracker brings manual entries and CSV imports into one ledger. Corrections, refunds, and repeated files should never quietly change what the numbers mean.

The decision that matters

One canonical ledger for recorded activity. Separate planning scenarios for exploring the future, so a hypothetical change never alters actual transactions.

What happens when the same file arrives twice?+

Durable import jobs retain source identity and row outcomes. Repeating the documented sample files keeps the same totals: USD 100 income and USD 40 net expenses. EUR 7.50 remains separate instead of being combined into a misleading total.

Ambiguous overlaps require a review decision. Saved planning scenarios support independent copies, cash reserve warnings, and exact decimal calculations.

02 / Resilient editingPersonal project
Local editOffline queueReconcile

An interrupted connection shouldn’t erase someone’s work.

In my clinical notes workflow, edits can survive offline sessions and meet conflicting changes when they reconnect.

The decision that matters

An IndexedDB write queue preserves local edits. Three way conflict resolution reconciles competing versions, while a state machine defines the review transitions.

Mock API and synthetic data. Pagination and virtualization support browsing 100K synthetic records.

02 / My approach

Start with what
could go wrong.

The questions I bring to a new workflow, before reaching for another tool.

01

Find the invariant.

What must remain true? A repeated import must not change the totals. An edit must not disappear. Make that promise explicit.

02

Design the recovery.

Connections fail and responses vary. Give retries, conflicting changes, and uncertain matches a deliberate path forward.

03

Make it observable.

Show what happened and what comes next. Row outcomes, review states, and validation results help people understand the system.
