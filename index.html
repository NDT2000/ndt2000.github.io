01 / Resilient collaborationPersonal project · Synthetic data

AI assisted clinical notes workflow

A note can change hands.
The work should never get lost.

Clinicians, reviewers, administrators, and auditors need different ways to work with the same clinical note. I built a review application that carries a structured SOAP note through review, approval, amendment, and lock, with a clear record of what changed.

The decision that matters

Define workflow rules once, share them between the UI and API, and enforce every mutation on the server. A valid action depends on the note’s state, the person’s role, and who owns the review.

Edits that survive interruption

Coalesced autosave and a persistent IndexedDB queue preserve drafts through network loss and reloads. Three way conflict resolution handles competing versions instead of silently overwriting them.

Collaboration with context

WebSocket updates and presence show other people’s activity. A “While you were away” panel explains missed changes after reconnection.

History that stays intact

Every save creates an immutable version. Word level comparisons explain content changes; review events preserve the workflow history.

Where the hard engineering lives+

Recover without overwriting

Only one save per note runs at a time. Offline writes replay in order, and local, server, and common ancestor versions support automatic merging of changes that do not overlap.

Keep client and server aligned

A shared JSON contract defines transitions, guards, and messages. The backend remains authoritative, and API types are generated from the OpenAPI contract.

Reconnect without losing context

Event deduplication, cursor replay, and reconciliation handle interrupted live connections. Redis relays events across API processes; presence reports who is viewing or editing a note.

Check the boundaries

The documented suites cover workflow parity, authorization, conflicting saves, immutable versions, offline replay, and telemetry redaction. CI also checks Compose startup and restart behavior.

All patient and note data is synthetic. This is a personal engineering project, not a deployed clinical system. The README documents remaining limits, including simulated MFA, planned RAG generation, and no browser driven end to end suite yet.

02 / Financial dataPersonal project · In development

Financial insights start with numbers you can trust.

Personal Finance Tracker brings manual entries and CSV imports into one ledger. Corrections, refunds, and repeated files should never quietly change what the numbers mean.

The decision that matters

One canonical ledger for recorded activity. Separate planning scenarios for exploring the future, so a hypothetical change never alters actual transactions.

What happens when the same file arrives twice?+

Durable import jobs retain source identity and row outcomes. Repeating the documented sample files keeps the same totals: USD 100 income and USD 40 net expenses. EUR 7.50 remains separate instead of being combined into a misleading total.

Ambiguous overlaps require a review decision. Saved planning scenarios support independent copies, cash reserve warnings, and exact decimal calculations.

02 / My approach

Start with what
could go wrong.

The questions I bring to a new workflow, before reaching for another tool.

01

Find the invariant.

What must remain true? A repeated import must not change the totals. An edit must not disappear. Make that promise explicit.

02

Design the recovery.

Connections fail and responses vary. Give retries, conflicting changes, and uncertain matches a deliberate path forward.

03

Make it observable.

Show what happened and what comes next. Row outcomes, review states, and validation results help people understand the system.
